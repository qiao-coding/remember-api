# 常见问题

使用 remember-api 时最常被问到的几件事。更多细节见[核心概念](/docs/concepts)与[OpenAI 兼容 API](/docs/api)。

## 换工具 / 换设备，它还认不认得我？

认得。所有客户端都接到同一个网关、同一个账号下的同一个人 model——它的记忆与 Skills 是共享的。在 A 工具里告诉它的事，到 B 工具提问时会自动带上，不需要重新介绍自己。

## 记忆到底存在哪？

存在你这个实例自己的数据库（Postgres）里，归你所有。发给上游模型的内容只有「当前这一次请求」的上下文，记忆本体不会上传到第三方。

## 想让两个场景互不混淆怎么办？

按你的隔离需求二选一：想让两边连记忆都分开，就建两个不同的个人 model（各绑一个 key）；想共享「你这个人」的偏好、但项目背景不串，就在同一个 agent 下用不同项目——记忆按项目分桶。

## 请求报了 403 / profile_not_allowed 是什么原因？

每个 key 都绑定一个个人 model，这次请求了「其它 model」，或带了 `remember.project`。key 只能调它绑定的那一个 agent；把请求改回绑定 model（或另建一个绑到目标 model 的 key）即可。

## API Key 明文忘复制 / 丢了怎么办？

明文只在创建时显示一次，数据库只存哈希，无法找回。直接删除旧 key 重建一个，把新 key 填进客户端。

## 怎么清空某段记忆、或让它别再记？

控制台「Memories」页能查、能改、能删具体的记忆条目。想整个停用某个人 model 的记忆，就在 Profiles 里关掉它的「记忆」开关——之后对话不再注入旧上下文，也不写回新记忆。

## 客户端能直接填 deepseek-chat 这种上游原始名吗？

不推荐。请填 `/v1/models` 返回的名字——也就是你的个人 model 名。即使填了上游别名也会被当作绑定 model 处理；未命中任何个人 model 的名字会被 404 拒绝。

## 这个网关支持哪些客户端？

任何支持 OpenAI 兼容接口的工具都可以：Claude Code、Codex、Cursor、opencode、以及各类自建 Harness 等。它对这些工具而言只是一个「模型供应商」。
