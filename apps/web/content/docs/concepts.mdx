# 核心概念

remember-api 本质是一个 OpenAI 兼容网关：把「你的个人 AI」拆成几个好理解的单元——个人 model、API Key、项目与记忆、Skills、上游 Provider。记住一句话：**一个个人 model = 一个子 agent**，所有东西都围绕它转。

## 个人 model（Profile）—— 隔离单元

「个人 model」是网关里的核心概念，也是客户端要填的「模型名」。它不只是一个模型配置，而是一个有独立人格与上下文的小 agent：

- 配置指向某个上游（Provider）和真实模型（如 deepseek），并带自己的 system prompt、温度等参数；
- 可以**开启/关闭记忆**，控制它每次对话是否带上之前沉淀的偏好与上下文；
- 可以**挂载若干 Skills**，把常用规则/代码风格固定注入；
- 一个 profile 可关联一个项目——它的记忆默认落进那个项目的记忆桶。

客户端在 `/v1/models` 里看到的每个名字，就是一个可用的个人 model；填那个名字去调用即可。

## API Key —— 访问凭证，两种粒度

所有 `/v1` 请求都靠 API Key 认证（`Authorization: Bearer …`，通常以 `rma_` 开头）。**每个 key 都强制绑定一个个人 model（子 agent）**，只能调用它绑定的那一个——请求其它 model 或尝试覆盖项目都会被 403 拒绝。一个客户端配一个专属 agent，彼此隔离。

明文只在创建时显示一次（数据库只存哈希）。可以自定 secret，也可以留空让系统生成；随时可禁用或删除。删掉个人 model 时，绑定它的 key 会一起级联删除，避免 key 意外「宽化」成访问其它 agent 的权限。

## 项目与记忆

记忆按「用户级 + 项目级」分层保存。一个项目有自己的记忆桶；当个人 model 关联了项目，绑定它的 key 记忆只会落在「这个 model 的个人桶 + 该项目桶」里——A 项目记下的事实不会带进 B 项目。

- 个人偏好、长期事实与决策会沉淀成结构化记忆条目，随请求自动注入；
- 控制台 Memories 页可查、可改、可删——记错了随时纠正，不是黑箱。

## Skills —— 共享的固定规则

Skill 是一段可复用的规则/上下文片段。你可以在控制台写好「项目代码规范」「回答风格」等，再让某个个人 model 挂上它——该 model 每次对话都会带上这份固定内容，不需要重复贴。

## 上游 Provider —— 背后的真实模型服务

网关自己不跑模型：个人 model 的 Provider 指向真实上游（deepseek / openai / anthropic / openrouter，或自定义 OpenAI 兼容地址）。上游的 API Key 与地址在控制台集中管理、服务端加密存储，不会在页面回显。

> **关系速记**：API Key（绑定）→ 个人 model（Profile）→ Provider 的某个模型 →（可选的）项目记忆桶。一个 key 锁一个 agent；一个 agent 有独立记忆与规则。
