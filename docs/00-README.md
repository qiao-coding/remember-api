# remember-api Web 控制台文档目录

> **产品锚点**：remember-api 是**个人单用户**的 Stateful Personal AI API（OpenAI 兼容网关 + 记忆 + 控制台）。Web 端是**控制平面，不是聊天产品**——它负责让用户配置 API、管理记忆、观察成本，然后把 Base URL / API Key / Model 三项连接信息复制到任意 OpenAI 兼容客户端。

本目录参照 Loquar 的 docs 组织方式（编号里程碑 + 设计文档分离），为 **Web 控制台重做** 整理的一套**规格级蓝图**：照图施工，实现时无需再猜。

## 阅读顺序

1. **范围先行**：`01-需求与范围.md` —— 判断某个念头是否在 P0 内。
2. **了解当前欠账**：`web-ux/01-现状审计.md` —— 知道重做要修什么、修的顺序。
3. **对照数据源**：`03-接口契约.md` —— 任何字段问题先查这里，不猜后端。
4. **动手施工**：`web-ux/02-信息架构与导航.md`（外壳）→ `web-ux/04-组件规范.md`（基建）→ `web-ux/03-页面规格.md`（逐页）→ `web-ux/05-验收清单.md`（收口）。
5. **整体排期**：`02-开发计划.md` 的 M0–M3 里程碑。

## 文档约定

- **正文中文**，领域名词保留英文（Profile / Project / Memory / Skill / API Key / Provider / Usage / Dashboard…）。
- **取材来源标注**：每份新文档首部「取材来源」字段指向 `_legacy/` 或代码路径，便于追溯；旧文档不复制粘贴长文，只提炼结论并标注来源。
- **现状 vs 目标**：`web-ux/01-现状审计.md` 描述**当前**（as-is 快照，标注日期 2026-09-05）；其余文档描述**重做后目标**（to-be 规格）。页面规格中的 file:line 引用仅存在于现状审计中。
- **状态图例**：`[ ]` = 未做，`[x]` = 已符合目标（重做后由验收清单更新）。
