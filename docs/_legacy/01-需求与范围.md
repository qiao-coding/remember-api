# 01 · Web 控制台需求与范围

> **取材来源**：`_legacy/PRODUCT-DIRECTION.md`（产品四层与原则）、`_legacy/WEB-CONSOLE-UX.md`（Product principles / IA / P0 boundary）、`_legacy/acceptance-checklist.md`、仓库根目录中文需求文档（单用户定位）、当前代码审计（`web-ux/01-现状审计.md`）。
>
> **性质**：to-be 目标规格。本文界定「做什么 / 不做什么」，页面细节见 `web-ux/03-页面规格.md`。

## 1. 定位

**Web 端是 remember-api 的 Control Plane（控制台），不是聊天产品。**

它不聊天、不生成任务、不替代任何 AI 工作台（Harness）。它负责让用户完成三件事：

1. **配** —— 配置 Provider / Project / Profile / Skill / API Key；
2. **看** —— 查看记忆、用量、成本、上下文开销；
3. **改** —— 修正自动写入的错误记忆、固定重要记忆、维护项目上下文。

> **Core experience（对标的唯一成功判据）**：用户打开后台，创建 Project / Profile / API Key，确认记忆注入与用量统计，然后把 **Base URL / API Key / Model** 三项复制到任意 OpenAI 兼容客户端即完成一次接线。

**单用户产品**：个人 AI API，无多租户团队空间。UI 中的账号只服务「当前登录的这一个用户」。

## 2. 产品原则与经验含义

| # | 原则 | UI 上的经验含义 |
|---|---|---|
| P1 | **Control plane, not chat** | 第一屏是 Dashboard 不是聊天框；页面以「资源 / 配置 / 统计」为骨架。 |
| P2 | **Profile is model** | Profile 名就是客户端填的 `model`。UI 上 Profile 需展示它对应的完整连接语义（model / provider / project / memory 开关）。 |
| P3 | **Configuration is inspectable** | Profile、Project、Provider、Skill 的状态都要一眼可见（绑定关系、是否连接、memory 开关）。 |
| P4 | **Memory is editable** | 自动记忆不是神谕。记忆的查看 / 编辑 / 删除 / 固定必须是 P0。 |
| P5 | **Cost is first-class** | Usage 页和 Dashboard 都展示 memory overhead（记忆多烧了多少 token）。 |
| P6 | **Developer console tone** | 高信息密度、低装饰、清晰的表格与表单；不追求营销型视觉。 |
| P7 | **Safe defaults & honest states** | 无数据 / 加载 / 错误 / 未连接 provider 都要有**明确且诚实**的状态——错误绝不能伪装成空数据。 |

## 3. 信息架构（Section 职责总览）

| Section | Job（控制台里的职责） |
|---|---|
| Dashboard | 今天 / 近 7 天请求、token、成本、延迟、活跃 Profile / 最近 API Key / Project 一览。 |
| Profiles | 管理客户端看到的 `model`：provider、base model、project 绑定、memory 开关与预算、skill 绑定、system prompt。 |
| Projects | 管理项目上下文：摘要 / 架构 / 状态 / 决策 / 已知问题。 |
| Memories | 搜索、创建、编辑、删除、固定记忆；区分全局与项目记忆。 |
| Skills | 创建 / 编辑 / 删除 prompt fragment，查看 token 估算与「被哪些 Profile 使用」。 |
| Usage | 请求明细、token breakdown、cache hit、memory overhead、估算成本。 |
| API Keys | 创建 / 禁用 / 删除 `rma_` 调用密钥；明文仅创建时显示一次。 |
| Providers | 配置供应商 key / base URL / default model，**每 provider 一把加密 Key**（`provider_configs`，模型调用路径直接读它）。 |
| Docs（公开文档站） | 公开 `/docs`：快速开始 / 核心概念 / OpenAI 兼容 API / FAQ；登录后快速开始顶部显示真实连接信息。 |
| Settings | 账号信息与退出。 |

## 4. 范围（P0 / 显式不做）

### P0 —— 必须做

- 登录与路由保护（GoTrue 密码登录；未登录重定向）。
- 应用外壳：侧栏导航、顶栏、浅色/深色、移动端抽屉。
- **每个资源页的 CRUD**：Profiles / Projects / Memories / Skills / API Keys / Providers。
- Memory 搜索 / 过滤（type、project、pinned）/ 编辑 / 删除 / 固定 / 重要度调整 / 来源与时间展示。
- Usage 汇总 + 最近请求明细；memory overhead 展示。
- 登录态真实连接信息（公开 `/docs/quickstart` 顶部，仅登录渲染、可复制）。
- **全站空 / 载 / 错状态**：任何数据页在后端不可用时明确报错，而非显示成空。
- **删除/禁用需确认**；API Key 明文仅显示一次。

### 显式不做（Deliberately deferred）

| 不做 | 原因 |
|---|---|
| 注册 / onboarding 向导 | 单用户，账号由 SQL/运维预建 |
| 复杂可视化编辑器 | 控制台不是创作工具 |
| Memory merge review workflow | 预算内不需要 |
| 单次 request trace 详情页 | 先用 Usage 明细即可 |
| 聊天主界面 / Agent 执行循环 | 控制台不是聊天产品 |

> **已移出本表**：原「多 provider 路由策略 —— 后端 V1 仅 DeepSeek 完整可用」。该理由是当时的全局单把 `UPSTREAM_API_KEY` 造成的，现已失效：`provider_configs` 接进了模型调用路径（每 provider 一行、AES-256-GCM 加密的 Key + 自己的 baseUrl），provider 清单来自 models.dev 快照（213 家 / 7500+ 模型），控制台 Providers 页与 `npx remember-api model` 共用同一张表。**多 provider 从「不做」变成 P0 的一部分。**

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 桌面 | ≥1024px 无需横向滚动；表格横向滚动只限表格内部，页面整体不错位。 |
| 移动 | 能打开导航并操作核心表格；表单单列。 |
| 深色 | 全站可读：表格、输入框、卡片、图表都必须有深色适配；提供**手动切换**（默认跟随系统）。 |
| 无障碍 | 主操作必须是按钮/表单控件；不依赖悬浮文本表达状态；Memory 固定状态要有文字不只图标；复制按钮可键盘聚焦。 |
| 文案 | **UI 中文统一**（`lang="zh-CN"`）；领域名词保留英文（Profile / Memory / API Key…）；不出现半中半英的界面标签。 |
| 数据诚实 | 后端挂了显示「加载失败，请确认后端服务可用」，**不能**显示成空表「暂无」。 |
| 成本单位 | 人民币 `¥`（估算成本）。 |
| 日期 | 统一格式；关键列表给相对时间或明确时区；Memory 列表必须有日期列。 |

## 6. 对「记忆共享 + 用户隔离」的 UI 含义

- **同账号跨设备共享**：Profile / Memory 属于当前登录用户，换设备登录同一账号即见同一套数据——UI 无需多设备概念。
- **用户间隔离**：数据层按 `userId` 隔离。UI 上账号菜单显示当前用户 email，设置页注明「本实例为单用户」。
- API Key 明文只在创建时显示一次 → **复制按钮必须可键盘聚焦、无悬浮文本依赖**；刷新/离开后不再可查（列表只存 prefix + last4）。
