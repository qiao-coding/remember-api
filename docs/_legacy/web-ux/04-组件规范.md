## 1. 设计 token（CSS 变量化 · 现行 = Prisma 经典深海军/teal）

实现在 `apps/web/app/globals.css`（Tailwind v4 写法）：`@theme inline { --color-X: var(--X) }` 把每个语义色接到同名 CSS 变量，`:root`（light）与 `.dark` 定义两套值；半径刻度由 `calc(var(--radius) * n)` 派生（`--radius: 0.5rem`）。换色只改变量、不扫全站。

**Dark `.dark`（产品默认观感 = Prisma docs 经典暗色）**

| 变量 | 值 | 变量 | 值 |
|---|---|---|---|
| `--background` | `#131420`（深海军/炭） | `--foreground` | `#f7fafc` |
| `--card` / `--popover` | `#1a202c` | `--muted` / `--secondary` | `#1d242f` |
| `--primary` | `#16a394`（品牌 teal） | `--primary-foreground` | `#ffffff` |
| `--accent` | `#0d3a38` | `--accent-foreground` | `#71e8df`（浅 cyan-teal） |
| `--border` / `--input` | `#1d242f` | `--ring` | `#16a394` |
| `--muted-foreground` | `#a0aec0` | `--destructive` | `#e53e3e` |
| `--sidebar` | `var(--background)` | `--sidebar-accent` | `#1d242f` |

**Light `:root`**：白底 + `--foreground:#1d242f`、`--muted-foreground:#718096`、`--border:#e2e8f0`、teal `--primary:#16a394`、`--accent:#d9f9f6`/`--accent-foreground:#154f47`、`--secondary:#f7fafc`。

- **状态色**（Badge 状态变体、警示）不设独立变量，直接取 Tailwind 语义：success→`emerald`、warning→`amber`、危险→`--destructive`。
- 品牌点缀（login 右栏、光谱细线）用 Prisma 棱镜光谱渐变 `linear-gradient(85deg,#01d7e4,#f3c306,#f37a03,#f43531,#f00e5c)`（抓取自 prisma.io），仅作 accent，不做大面积填充。
- 字体：`--font-sans` = 系统中文栈（含 PingFang SC / Microsoft YaHei）；`--font-mono` 用于 key/code/表格数值。

## 2. 主题机制（现行）

- `next-themes`（`attribute="class"`，`enableSystem`）挂 `html` 的 `.dark`，覆盖同一组变量；Provider 默认 `dark`，用户经顶栏 `ThemeToggle` 手动切换后选择持久化于 localStorage。**已废除**旧的 `prefers-color-scheme` 媒体查询双轨（globals.css 只留 `.dark { color-scheme: dark }`）。
- 组件一律消费 token 语义类（`bg-card` / `text-muted-foreground` / `bg-primary` …），不写散点色值、不写 `dark:` 手动分支。

## 3. 组件契约（补进 `components/ui.tsx`）

**约定**：所有组件默认浅色 + 深色两态；语义色从 token 取；键盘可达；`cn()` 合并类。现有保留：`Button/Card/CardHeader/Input/Textarea/Badge/Table 系/StatCard`（缺失 size 补齐）。需**新增**：

| 组件 | 用途 / Props（要点） | 状态 |
|---|---|---|
| `Select` | 原生 `<select>` 封装，统一外观 | 有 label 外置；error 态红描边 |
| `Field`+`Label` | 表单字段容器：label + 控件 + hint + error | 必填星标、错误文案 aria |
| `Switch` | 布尔开关（memoryEnabled / pinned 等） | 选中/禁用 |
| `Checkbox` | 复选（skill 多选） | — |
| `Dialog` | 创建/编辑表单容器（居中、overlay、Esc/点外关闭、焦点圈闭） | — |
| `ConfirmDialog` | 危险操作确认：标题 + 说明 + 取消/确认（danger 主按钮） | 异步 pending 态 |
| `EmptyState` | 空态：图标 + 标题 + 说明 + 可选主操作 | — |
| `Skeleton` | 加载骨架 | — |
| `Spinner` | 行内加载 | — |
| `PageHeader` | 页标题 + description + 右侧 action 区（统一主按钮位） | — |
| `Toast` | 全局轻提示（成功/错误）；与 React Query 整合 | — |
| `CopyButton` | 复制（text prop + 成功反馈），键盘可达 | — |
| `DateCell` | 统一日期格式（相对/绝对 + title 全量） | — |
| `Pagination` | 列表分页（当前无，先给 usage/memories 大列表） | — |

**表格三态行约定**：`Table` 接受 `loading/empty/error` props → 分别渲染 `Skeleton 行` / `EmptyState colSpan` / 错误行 + 重试。这直接封掉 P0-1/P0-2/P1-5 的重复。

## 4. 数据层模式（照图施工含代码约定）

- **统一请求**：复用 `lib/api.ts` `apiFetch<T>`；不再散写 `fetch` + 手拼 header。
- **标准 query key**（消灭审计 P1-8）：
  - `["profiles"]` `["projects"]` `["skills"]` `["keys"]` `["providers"]`
  - `["memories", {q, projectId, type, pinned}]`
  - `["usage","summary", days]` `["usage","requests", limit]` `["usage","breakdown", groupBy, days]`
- **变更失效语义**：mutation 成功后 `invalidateQueries` 对应 key（如建 Profile 后失效 `["profiles"]`，同时 `["usage","summary"]` 不受影响）。
- **共享列表/表单 hook**（可选，消除 6 页样板）：`useResourceList(key, fetcher)` + `useCrud(…create/update/delete)`，各页只声明列定义与表单 schema。
- 名称 join 约定：usage breakdown/row 需名称时，页面拉 `/api/profiles`、`/api/projects` 建 `Map`，不发明新端点（见 `03-接口契约` §8 提示）。

## 5. 文案规范

- UI 界面文案 **zh-CN**；领域名词保留英文（Profile / Project / Memory / Skill / API Key / Provider / Usage / token / model）。
- 页面名/导航 = 英文领域词（Dashboard / Profiles…）；按钮、说明、状态、Toast = 中文。
- 状态文案口径统一（见 `02-信息架构` §5）：加载 / 空 / 错误三态文案固定模板，避免中英混排。
- 金额统一 `¥`；token 单位提示（如 `~N tokens`）。
