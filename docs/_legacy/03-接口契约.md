# 03 · Web 消费的接口契约（/api）

> **取材来源**（当前代码，快照 2026-09-05）：`apps/api/src/routes/manager/*.ts`（端点与字段）、`apps/api/src/app.ts`（错误格式）、`apps/web/lib/types.ts`（视图类型）、`apps/web/lib/api.ts`（401 语义）、`apps/web/middleware.ts` + `next.config.mjs`（代理）。
>
> **性质**：事实源。页面规格（`web-ux/03`）的任何字段问题先查本文件，**不猜后端**。若后端改动，先更新本文件。

## 0. 认证与代理

| 项 | 规则 |
|---|---|
| 登录 | Web 端浏览器 `@supabase/supabase-js` 的 `signInWithPassword` **直达 GoTrue**（`POST <SUPABASE_URL>/auth/v1/token?grant_type=password`），不经 Fastify 代理。后端 `/api` **没有**登录端点。 |
| 后台请求鉴权 | 每个 `/api/*` 请求头带 `Authorization: Bearer <access_token>`（Supabase JWT）。封装见 `lib/api.ts` 的 `apiFetch<T>(path, init?)`。 |
| 401 语义 | `apiFetch`：401 且原本带 session → `refreshSession()` 重试一次；仍 401 → `signOut()` 并跳 `/login`。调用方无需自处理。 |
| 错误体 | 非 2xx 返回 `{ error: string }`；`apiFetch` 抛 `ApiError(status, message)`，`message` 取 `body.error`，取不到时回退 `请求失败 (status)`。 |
| 代理 | `middleware.ts` 放行 `/api`、`/v1` 前缀（直通 Fastify，鉴权在服务端做）；其余路径由 `@supabase/ssr` 校验登录，未登录跳 `/login?next=<path>`，已登录访问 `/login` 跳 `/dashboard`。`next.config.mjs` 把 `/api`、`/v1` rewrite 到 `API_URL`（默认 `http://localhost:4000`）。 |
| 环境变量 | `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`、`API_URL`。 |

> **Web 需要的 `/api` 响应视图类型全部在 `apps/web/lib/types.ts` 定义**：`ProfileView / ProjectView / SkillView / KeyView / KeyCreated / ProviderView / MemoryItem / UsageSummary / UsageRow / UsageBreakdown`。本文件用「= 类型名」标注响应类型，页面规格引用同一类型，保证三处一致。

| Method | Path | 请求体 | 响应 |
|---|---|---|---|
| GET | `/api/profiles` | — | `ProfileView[]`（含 projectName join） |
| GET | `/api/profiles/:id` | — | `ProfileView`；不存在 404 |
| POST | `/api/profiles` | `ProfilePayload` | `{ id }` |
| PATCH | `/api/profiles/:id` | `ProfilePayload`(partial) | `{ ok: true }` |

`ProfileView = { id, name, provider, model, projectId: string\|null, projectName: string\|null, systemPrompt: string\|null, memoryEnabled: boolean, memoryBudget: number, skillIds: string[], temperature: number\|null, maxTokens: number\|null, createdAt, updatedAt }`

`ProfilePayload`（POST 全量 / PATCH partial）：
| 字段 | 类型 | 必填 | 约束 / 默认 |
|---|---|---|---|

| `model` | string | ✅ | 真实上游模型名，如 `deepseek-chat` |
| `projectId` | string\|null | — | 默认无绑定；需属于当前用户 |
| `systemPrompt` | string\|null | — | |
| `memoryEnabled` | boolean | — | 默认 `true` |
| `memoryBudget` | int | — | 100–100000，默认 1500 |
| `skillIds` | string[] | — | 需属于当前用户 |
| `temperature` | number\|null | — | |
| `maxTokens` | int\|null | — | |

## 6. Providers

| Method | Path | 请求体 | 响应 |
|---|---|---|---|
| GET | `/api/providers` | — | `ProviderView[]` |
| POST | `/api/providers` | `ProviderPayload` | `{ id }`（upsert：每 provider 每用户唯一） |
| PATCH | `/api/providers/:id` | `ProviderPayload`(partial) | `{ ok: true }` |
| DELETE | `/api/providers/:id` | — | `{ ok: true }`；404 |

`ProviderView = { id, provider, baseUrl: string\|null, defaultModel: string\|null, isConnected: boolean, createdAt, updatedAt }` —— **永不返回 apiKey**。

`ProviderPayload`：`provider`(✅，非空 string，见上) + `baseUrl? / defaultModel?`(string\|null) + `apiKey?`(明文，仅创建/更新时提交)。
语义：
- 提交新 `apiKey` → AES-256-GCM 加密存库，`isConnected=true`；
- 不带 `apiKey` 但有旧值 → 保留旧加密值；
- `isConnected` = 有无已存 key。列表/读取接口永远拿不到明文。

> **模型调用路径会读 `providerConfigs`**（`apps/api/src/lib/upstream.ts`，单一路由点，优先级就写在文件头的注释里，改这里要同步改那边）：
> 1. `provider_configs(userId, provider)` 有行且解得开 Key → **用那一行的 Key 和 baseUrl**；
> 2. 否则回退 env `UPSTREAM_API_KEY` / `UPSTREAM_BASE_URL`（既有部署与测试行为不变）；
> 3. 该用户在**别家**配过 Key、唯独这家没有 → 抛 `ProviderError` → 400 `provider_not_configured`（必错配置不伪装成能跑）；
> 4. 一把凭据都没有 → `MockProvider`（开发态约定，boot 时告警）。
>
> 所以 UI 可以把它描述成「配了就能用」。`provider` 与 `baseUrl` **绑定**：Key 来自哪一行，baseUrl 就只取那一行或 models.dev 目录里该 provider 的 `api`，**不会**落到 env 的 `UPSTREAM_BASE_URL`（否则会把 A 家的 Key 发到 B 家的端点）。Provider 抽象对所有目录内的 provider 生效：`packages/providers/src/sdk.ts` 统一走 OpenAI 兼容协议，各家只是 baseURL 不同；目录里没有 `api` 的（openai / anthropic 等）必须在 `baseUrl` 里显式给，不猜。

## 7. Memories

**后端为 provider 抽象**（配了 `MEM0_BASE_URL` 走 Mem0 bridge，否则走 DB provider）。`type` 枚举（与 `lib/types.ts` `MEMORY_TYPE_LABEL` 对应）：`preference | decision | status | task | issue | history`。Memory 字段：`id, projectId: string\|null, type, content, importance(0–1), pinned, source, createdAt, updatedAt`；**搜索命中带 `relevance`**。

| Method | Path | 请求 | 响应 |
|---|---|---|---|
| GET | `/api/memories` | query：`q? projectId? type? pinnedOnly? limit?(默认50) offset?` | `MemoryItem[]` |
| POST | `/api/memories` | `{ content(✅), type(✅枚举), importance? 0–1(默认.5), pinned?(默认false), projectId?\|null }` | 创建后的 memory（`source:"user"`） |
| GET | `/api/memories/:id` | — | memory；404（不存在或非本人） |
| PATCH | `/api/memories/:id` | `{ content?, type?, importance?, pinned?, projectId?\|null }` | 更新后的 memory |
| DELETE | `/api/memories/:id` | — | `{ ok: true }`；404 |

`projectId` 语义（列表关键）：
- 缺省/`undefined` → **全局 + 项目记忆混合列表**；
- `"__global__"` → 只全局（projectId=null）；
- 具体 id → 只该项目。
`q` 存在时走搜索（返回含 relevance），否则走 list。

## 8. Usage

| Method | Path | 请求 | 响应 |
|---|---|---|---|
| GET | `/api/usage/summary` | `days=1|7|30`（默认1） | `UsageSummary` |
| GET | `/api/usage/requests` | `limit`（默认30，上限200） | `UsageRow[]`（createdAt desc） |
| GET | `/api/usage/breakdown` | `groupBy=profile\|project`（默认profile）、`days`（默认7） | `UsageBreakdown[]` |

`UsageSummary = { requests, inputTokens, outputTokens, cachedTokens, memoryTokens, skillTokens, cost, latencyMs, cacheHit(%), memoryOverhead, avgLatencyMs }`
`UsageRow = { id, profileId, projectId: string\|null, provider, model, inputTokens, outputTokens, cachedTokens, memoryTokens, skillTokens, latencyMs, estimatedCost, createdAt }`
`UsageBreakdown = { key, tokens, cost, requests }`（`key` = profileId 或 projectId）

> 页面需要 profile/project 名称来显示 breakdown/row 时，用 `/api/profiles`、`/api/projects` 名称 map 本地 join；后端不返回名称。

## 9. /v1（供 Docs 页展示参考，控制台不直接调用）

- `GET /v1/models`（Bearer `rma_` key）→ 当前用户 Profile 列表。
- `POST /v1/chat/completions`（OpenAI 兼容，SSE）。
Docs 页的「客户端配置」示例基于这两者，但**示例值必须来自真实数据**（base URL 可配、key 用创建态明文、model 取实际 Profile 名）。
