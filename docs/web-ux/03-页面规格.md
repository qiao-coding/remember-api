# web-ux/03 · 页面规格（照图施工主档）

> **事实源**：字段一律取自 `../03-接口契约.md` 与 `apps/web/lib/types.ts`，**不凭空造**。类型名（如 `ProfileView`）即该文件中的 interface。
>
> **通用约定**（每页都适用，不逐页重复）：
> - 四态：**加载**（Skeleton/行内「加载中…」）、**空**（`EmptyState`）、**错误**（后端不可用 → 明确报错 + 重试，不当空）、**正常**。
> - 所有删除/禁用走 `ConfirmDialog`；所有表单提交中禁用提交钮 + 防重复；成功/失败给 `Toast`。
> - 日期列用统一格式化组件；关键表给相对时间提示。
> - 语言 zh-CN，领域词英文。
> - 主按钮 = 每页 `PageHeader` 右侧「新建/＋」；行内操作：编辑 +（危险）删除。
> - 状态色：成功绿 / 危险红 / 警告琥珀 / 信息蓝（见 `04-组件规范` token）。

## 1. login

- **目标**：仅剩一个动作——登录当前用户。单用户无注册。
- 布局：居中卡片；品牌名 + email/password 输入 + 提交。
- 表单：`email`（必填、`type=email`）、`password`（必填、`type=password`、可 `Enter` 提交）。
- 交互：提交调 Supabase `signInWithPassword`（`03-接口契约` §0）；加载禁用提交钮 + spinner；失败显示 `invalid_credentials` 中文文案（不区分用户/密码错误以安全）；**提供「忘记密码」链接**可后置（P2）。
- 深色：卡片与输入随主题。
- 验收：正确凭证 → 跳 `/dashboard`；错误凭证 → 卡内错误、无跳转；未登录访问受保护页 → 落回本页带 `next` 回跳。

## 2. dashboard

- **目标**：打开后台立刻知道 API 使用状态（近 7 天）。修：四面板统一列表组件、StatCard 加载统一「—」。
- 布局：顶部 4×`StatCard`，下方面板网格（Profiles / API Keys / Projects / Providers 预览）。
- StatCard（7 天，数据 `/api/usage/summary?days=7`）：
  | 卡 | 值字段 | 副标 |
  |---|---|---|
  | 请求数 | `requests` | 近 7 天 |
  | Tokens | `inputTokens+outputTokens` | in/out/cached 细分 |
  | 估算成本 | `cost` | 单位 `¥` |
  | 平均延迟 | `avgLatencyMs` | ms |
  - **加载**：`—`（不是 `0`）。
- 面板：
  - Profiles（前 5）：`name` + `provider/model` + projectName 徽标；无数据 EmptyState。
  - API Keys（前 5）：`name` + `prefix…last4` + 启用/禁用 Badge + `lastUsedAt`。
  - Projects（列表）：`name` + `status` + updatedAt。
  - Providers：`provider` 名 + isConnected Badge「已连接/未连接」；未连接给「去配置」。
  - 统一用同一列表样式（全 `ul` 或全 `Table`，不要 table/ul 混搭，修 P2-7）。
- 深色：卡片/列表随 token；无误判。
- 验收：有数据时与 `/api/usage/summary` 一致；无数据各面板显示 EmptyState；后端挂显示错误态；StatCard 加载为「—」。

## 3. profiles（CRUD 中心）

- **目标**：管理「客户端看到的 model」。Profile = model 名。
- 表格列（`ProfileView`）：
  | 列 | 字段 | 渲染 |
  |---|---|---|
  | 名称 | `name` | 等宽（客户端要填的值） |
  | Provider | `provider` | 文本（当前恒 deepseek） |
  | 模型 | `model` | 等宽 |
  | 项目 | `projectName` | 无 →「—」 |
  | 记忆 | `memoryEnabled` | 开关状态 Badge「开/关」；`memoryBudget` 悬停/辅助显示 |
  | 更新 | `updatedAt` | 格式化 |
  | 操作 | — | 编辑 / 删除 |
- 新建/编辑表单（Dialog；字段见 `ProfilePayload`）：
  - `name` 必填（提示：将作为客户端 `model`）；
  - `provider` = **deepseek 只读/单选标签**（后端仅此值，修 P0-5：不写死裸 option，数据/常量驱动 + 说明）；
  - `model` 必填（如 `deepseek-chat`）；
  - `project` 绑定：必选下拉取 `/api/projects`（强制；每个个人 model 必须属于一个项目）；
  - `systemPrompt`：多行文本域；
  - `memoryEnabled`：`Switch`；
  - `memoryBudget`：数字 100–100000，默认 1500；
  - `skillIds`：`/api/skills` 复选框组多选；
  - `temperature` / `maxTokens`：数字，可空（空=用后端默认）。
- 校验：name/model 非空；project/skill 必须属于本用户（后端已校验，前端友好报错）。
- 删除：`ConfirmDialog`，文案提示「删除后 `/v1/models` 不再返回该 model」。
- 验收：创建后 `/v1/models` 立即可见该 name；编辑保存后用新值；空态/错误态存在；provider 无假多选。

## 4. projects

- **目标**：项目上下文可人工维护（记忆纠错的第一性）。
- 表格列（`ProjectView`）：
  | 列 | 字段 |
  |---|---|
  | 名称 | `name` |
  | 状态 | `status`（无 →「—」） |
  | 摘要 | `summary`（截断） |
  | 决策数 | `decisions.length` |
  | 问题数 | `knownIssues.length` |
  | 更新 | `updatedAt` |
  | 操作 | 编辑 / 删除 |
- 表单（Dialog）：
  - `name` 必填；
  - `description` / `summary` / `architecture` / `status`：多行/单行文本域；
  - `decisions` / `knownIssues`：**列表编辑器**（可增删条目，替代换行 join/split）；每条文本。
- 删除确认：`ConfirmDialog`，提示「删除后其记忆与绑定此项目的 Profile 关联受影响（Profile.projectId 置空）」。
- 记忆/用量 tab 后续（P2）；本规格不含。
- 验收：数组字段增删正确往返；删除有确认；不同项目列表互不污染（数据层已保证，UI 不越权）。

## 5. memories（最复杂页）

- **目标**：记忆可见、可改、可控。功能最全，保留并升级现有页。
- 过滤/搜索区：
  - 文本搜索 `q`（回车/防抖）；类型下拉 `type`（`MEMORY_TYPE_LABEL`：偏好/决策/状态/任务/问题/历史 + 全部）；项目下拉 `projectId`（选项：全部 / 仅全局 `__global__` / 各项目）；`pinnedOnly` 开关；`limit`。
- 表格列（`MemoryItem`）：
  | 列 | 字段 | 渲染 |
  |---|---|---|
  | 内容 | `content` | 截断 + title；**新加日期可排序**（修 P1-6） |
  | 类型 | `type` | 按 label 映射的 `Badge` 色 |
  | 归属 | `projectId` | 全局 →「全局」Badge；项目 → 项目名（join `/api/projects`） |
  | 重要度 | `importance` | 0–1 数值或条 |
  | 固定 | `pinned` | `Switch` + 文字（不只图标） |
  | 来源 | `source` | 文本（user/auto…） |
  | 时间 | `createdAt` | 格式化（**必须有，修审计缺失**） |
  | 相关度 | `relevance` | 仅搜索时显示（% ） |
  | 操作 | — | 编辑 / 删除 |
- 编辑：内容、类型、重要度滑杆(0–1)、pinned、归属项目。
- 删除确认：`ConfirmDialog`。
- 空/载/错：本页已达标，升级为组件化。
- 验收：可搜到关键词并显示 relevance；全局/项目清晰区分；可修错记忆并固定；深色下全部可读。

## 6. skills

- **目标**：管理 prompt fragment。
- 表格列（`SkillView`）：名称 `name` / 说明 `description` / tokens `tokenCount`（Badge「~N tokens」）/ 更新时间 / 操作。
- 表单：`name` 必填、`description`、`content` 必填多行（Markdown/TXT）；提交后 token 估算由后端返回，不手算。
- 「被哪些 Profile 使用」：join `/api/profiles` 的 `skillIds` 展示使用数（可选列）。
- 删除确认 + 空态（本页现缺，修 P0-2）。
- 验收：创建/编辑后 tokenCount 更新；删除有确认；空态显示。

## 7. usage

- **目标**：看 token / 成本 / overhead，判断记忆值不值。
- 顶：`StatCard`×4 + 窗口选择（1/7/30 天）。**加载统一「—」**（修 P0-7）。StatCard：请求数 / Tokens（in·out·cached）/ 成本 `¥` / memory overhead（`memoryOverhead`）+ cache hit 辅助。
- 图表：按 Profile 或 Project 的 token breakdown（`/api/usage/breakdown?groupBy=&days=`）：
  - **fill 用语义 token 色，禁用硬编码十六进制**（修 P0-3：深色下不可见）；
  - 空数据 → 空图占位（EmptyState 图区）。
- 明细表（`/api/usage/requests`，`UsageRow`）：时间 / model / profile / provider / in / out / cached / memory / skill / latency / 成本。`limit` 选择（10–100）。
- profileId/projectId → 名称 join profiles/projects map；未知显示 id。
- 验收：切 1/7/30 刷新；深色图表可见；空数据不白板；加载不为 0 误读。

## 8. keys

- **目标**：生成/吊销调用密钥。
- 表格列（`KeyView`）：名称 `name` / Key（`prefix…last4` 等宽）/ 状态（`disabled` → Badge「已禁用」）/ `lastUsedAt` / 创建时间 / 操作（禁用·启用 / 删除）。
- 新建：Dialog 输 `name` → POST → 返回 `KeyCreated`：
  - **一次性显文**面板：完整 `key` 等宽 + 复制钮（键盘可达）+ 警示「关闭后不再显示，请立即复制」+ 成功 Toast。
- 禁用/删除：均 `ConfirmDialog`；禁用后客户端调用即刻 401。
- 空态/载态齐全（现缺空行，修 P0-2）。
- 验收：新建即显明文一次，列表只有 prefix+last4；禁用后 `/v1` 调用失败；刷新不复显明文。

## 9. providers

- **目标**：配置供应商 key（当前 deepseek）+ 连接状态。
- Provider 卡（当前单项 deepseek）：
  - 头部：`provider` 名 + isConnected Badge「已连接/未连接」；
  - 字段：baseUrl（可空，等宽）、defaultModel、`apiKey`（`password` 类型，仅填写时提交，**回显永远留空 + 占位「已保存 key（不显示）」**）。
- 操作：**行内「编辑」**（修 P2-3，不再只能重填 create 表单）；删除配置。
- POST upsert 语义：不填 apiKey 保留旧 key（`03-接口契约` §6）。
- 空态 + 引导：无配置 → EmptyState「配置 DeepSeek key 以启用调用」。
- 验收：配置后可调用；刷新后 key 不回显；未连接态清晰；删除有确认。

## 10. docs

- **目标**：把三项连接信息交给用户复制。**示例值真实化**（修 P0-6）。
- 内容：
  - Connection 卡片：**Base URL**、**API Key**、**Model** 三项 + 复制钮。
    - Base URL 来源：部署配置值（`NEXT_PUBLIC_GATEWAY_URL`）或**本控制台同源 `/v1`**（`${origin}/v1`，经 next rewrite 直通后端）——绝不复现 `localhost:4000` 硬编码，除非明确是本地开发模式；
    - Model：取第一个可用 Profile 的 `name`（真实，无则提示先建 Profile）；
    - API Key：提示用刚创建的明文（引导到 keys 页），不静态占位假 `rma_…`。
  - 接入步骤卡（4 步：配置 Base URL / 创建并粘贴 API Key / 填 Model / 在 Claude Code·Codex·Cursor·DeepSeek Harness 中调用）。
- 服务端组件、无 /api 调用；示例值来自环境/首个 Profile。
- 验收：照抄示例能直接打通（本地开发时 base 指到运行中的网关）；不出现假的 `remember-dev`。

## 11. settings

- **目标**：账号信息 + 退出（单用户）。
- 内容：
  - 账号卡：`/api/auth/me` → email / name / id；
  - 退出按钮（`supabase.auth.signOut()` → `/login`）；
  - 环境/实例说明（可换成真实「单用户实例」说明，**移除静态 env 名列表** stub，修 P2-2）。
- 验收：能显示当前账号并干净退出；无残留「环境变量」伪设置项。
